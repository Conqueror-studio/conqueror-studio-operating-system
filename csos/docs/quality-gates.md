# Quality Gates and Definition of Done

## Mandatory gates

1. **Discovery:** signed brief, decision-maker, audience, goal, budget range, constraints.
2. **Direction:** approved Creative Bible, content plan, PDS/PRD, and acceptance criteria.
3. **Design:** approved responsive Figma states, components, tokens, accessibility notes.
4. **Build:** implementation follows starter, CDS, and AI rules; no scope drift.
5. **QA:** responsive checks, keyboard navigation, content/links/forms, metadata, performance review.
6. **Launch:** client approval, backups, analytics consent/configuration, domain and rollback plan.
7. **Learn:** retrospective, archive, and reusable learning captured.

## Definition of Done

A feature is done only when it meets approved requirements, works across agreed breakpoints, has accessible interaction and meaningful content, passes review, has no known critical defect, and is documented. A website is done only after all launch-gate items have named owner evidence. Lighthouse goals are targets, not a substitute for human QA.
